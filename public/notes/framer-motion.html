The React animation library that feels like React. Declarative props for fades, springs, gestures, layout transitions, and scroll effects — without the CSS keyframe wrangling or manual RAF loops.

01

Why Framer Motion exists

CSS transitions don't know React · the missing animation layer

CSS transitions and keyframes are great for hover states and simple fades. They fall apart the moment an animation depends on React state. Animating a modal out when it unmounts? CSS can't do it — the element is already gone. Animating a list reorder? You'd need the FLIP technique by hand. Scroll-linked parallax? A `requestAnimationFrame` loop with manual math.

Framer Motion (now officially **Motion** — the npm package is `motion`, import from `motion/react`) solves this by making animation a first-class part of React's render model. You describe the states, and it handles the interpolation, the interruptions, the springs, and the unmount timing.

The one sentence

Framer Motion turns animation into declarative React props: you say what the component should look like when isOpen is true, and it animates there — and back — automatically, with spring physics, gesture handling, and exit animations built in.

💡
Naming note. Framer Motion was renamed to Motion in late 2024. The old package framer-motion still exists, but new code should install motion and import from motion/react [citation:1][citation:3]. This guide uses the modern import path, but every concept applies to both.
Quick check · 01
What's the fundamental thing CSS can't do that Framer Motion solves?
Exit animations require keeping the element in the DOM until the animation finishes. Framer Motion's AnimatePresence does exactly that — CSS alone cannot, because React unmounts synchronously.
02

Setup & the motion component

install · motion.div · initial / animate / transition

terminal
npm install motion

Replace any HTML element with its `motion.` counterpart. It accepts all the normal props plus animation props: initial (the starting state), animate (the target state), and transition (how to get there).

basic-fade.tsx
import { motion } from 'motion/react';

function FadeIn() {
  return (
    <motion.div
      initial={{ opacity: 0, y: 20 }}
      animate={{ opacity: 1, y: 0 }}
      transition={{ duration: 0.4, ease: 'easeOut' }}
    >
      Hello
    </motion.div>
  );
}

What properties can you animate?

Almost anything CSS can: opacity, x, y, scale, rotate, backgroundColor, borderRadius, width, height. The transform properties (x, y, scale, rotate) are GPU-accelerated and are what you should reach for first.

⚠️
Animate transform properties, not layout properties. animate={{ x: 100 }} is fast (GPU compositing). animate={{ left: '100px' }} or animate={{ width: 200 }} forces the browser to recalculate layout on every frame — janky on slower devices [citation:10][citation:13]. This single choice separates animations that feel smooth from animations that feel broken.
Quick check · 02
Which animation is more performant?
x compiles to transform: translateX(), which the GPU can composite without touching layout. left forces the browser to recalculate the position of every element on the page — every frame.
03

Variants & orchestration

named states · inheritance · staggerChildren

Variants are named animation states defined outside the component. Instead of passing objects to initial and animate, you pass strings that reference the variant names.

variants.tsx
const cardVariants = {
  hidden: { opacity: 0, scale: 0.9, y: 20 },
  visible: { opacity: 1, scale: 1, y: 0 },
  exit: { opacity: 0, scale: 0.9 },
};

<motion.div
  variants={cardVariants}
  initial="hidden"
  animate="visible"
  exit="exit"
/>

Inheritance — the killer feature

When a parent has a variant and children have variants with matching names, the parent's state propagates down. You don't need to pass animate to every child.

staggered-list.tsx
const container = {
  hidden: { opacity: 0 },
  visible: {
    opacity: 1,
    transition: { staggerChildren: 0.08 },
  },
};

const item = {
  hidden: { opacity: 0, y: 16 },
  visible: { opacity: 1, y: 0 },
};

<motion.ul variants={container} initial="hidden" animate="visible">
  {items.map(i => (
    <motion.li key={i.id} variants={item}>
      {i.name}
    </motion.li>
  ))}
</motion.ul>

The staggerChildren transition on the parent causes each child's visible animation to start 80ms after the previous one. This is how every polished staggered list you've seen is built [citation:2][citation:3].

Why variants beat inline objects

Variants give you (1) a single place to define a state's look, (2) inheritance so you orchestrate children from the parent, (3) the ability to swap whole animation themes by changing one variant name. Inline objects are fine for one-off animations; variants are how you scale animation across a component tree.

Quick check · 03
A child motion.li has a variants prop but no animate prop. The parent has animate="visible". What happens?
Variant propagation is automatic when names match. The parent says "visible", and every descendant with a visible variant animates to that state — which is what makes orchestration possible.
04

AnimatePresence — exit animations

the one component everyone needs · modes · the key rule

When React removes a component, it's gone instantly. There's no chance for CSS to animate it out. AnimatePresence solves this: it keeps the element in the tree until its exit animation finishes, then unmounts it.

modal-exit.tsx
import { motion, AnimatePresence } from 'motion/react';

function Modal({ isOpen }) {
  return (
    <AnimatePresence>
      {isOpen && (
        <motion.div
          key="modal"
          initial={{ opacity: 0, scale: 0.95 }}
          animate={{ opacity: 1, scale: 1 }}
          exit={{ opacity: 0, scale: 0.95 }}
        >
          Modal content
        </motion.div>
      )}
    </AnimatePresence>
  );
}
⚠️
Two rules that break exit animations. (1) AnimatePresence must stay mounted — put it outside the conditional. If the whole AnimatePresence unmounts, it can't wait for anything. (2) Every direct child needs a stable key. Without it, React can't tell which element is exiting and which is entering, so exit animations never fire [citation:3][citation:9].

AnimatePresence modes

ModeBehaviourUse for
sync (default)Enter and exit overlapIndependent animations, list items
waitEnter waits for exit to finishPage transitions, modal swap
popLayoutExiting element leaves the flow; siblings animate into placeLists where removing an item should collapse the gap
page-transition.tsx
<AnimatePresence mode="wait">
  <motion.div
    key={pathname}   // change key on route change
    initial={{ opacity: 0, y: 12 }}
    animate={{ opacity: 1, y: 0 }}
    exit={{ opacity: 0, y: -12 }}
  >
    <Outlet />
  </motion.div>
</AnimatePresence>

Using key={pathname} means each route is a different "element" to AnimatePresence — the old one exits, then the new one enters. This is the standard page-transition pattern.

Quick check · 04
Your modal's exit animation never fires. What's the most likely cause?
The two most common causes: AnimatePresence unmounting along with its children, or a child without a key. It needs to stay in the tree to defer the unmount until the exit animation completes.

Gestures

whileHover · whileTap · drag · dragConstraints

Framer Motion has first-class props for interaction states. They animate automatically and revert when the interaction ends.

gestures.tsx
// hover + tap
<motion.button
  whileHover={{ scale: 1.05 }}
  whileTap={{ scale: 0.95 }}
  transition={{ type: 'spring', stiffness: 400, damping: 20 }}
>
  Click me
</motion.button>

// draggable card that snaps back to a boundary
<motion.div
  drag
  dragConstraints={{ left: -100, right: 100, top: -100, bottom: 100 }}
  dragElastic={0.2}
  whileDrag={{ cursor: 'grabbing' }}
/>
PropWhen it runsReverts after?
whileHoverPointer entersYes
whileTapPointer pressedYes
whileFocusElement focusedYes
whileDragDraggingYes
whileInViewScrolls into viewportOptional (once: true)

These are the props that make buttons feel like buttons and cards feel physical. The spring defaults on gestures are already tuned well — you rarely need to override them.

Layout animations

the layout prop · layoutId · LayoutGroup · FLIP under the hood

The layout prop is Framer Motion's superpower. Add it to an element and any time its size or position changes due to a React re-render, it animates the change — no from-value required. Under the hood it uses the FLIP technique (First, Last, Invert, Play): measure before, measure after, invert the difference with a transform, then animate it back to zero [citation:3][citation:14].

layout.tsx
// The box resizes smoothly when isExpanded changes
<motion.div
  layout
  style={{ width: isExpanded ? 400 : 200, height: isExpanded ? 200 : 100 }}
/>

layoutId — shared element transitions

Give two different elements the same layoutId. When one unmounts and the other mounts, Framer Motion animates between them as if it's the same element. This is how you build the "card expands into a modal" effect.

shared-layout.tsx
{!selected ? (
  <motion.div
    layoutId="card"
    onClick={() => setSelected(true)}
    style={{ width: 200, height: 120 }}
  />
) : (
  <motion.div
    layoutId="card"
    onClick={() => setSelected(false)}
    style={{ width: 600, height: 400 }}
  />
)}
⚠️
Text distortion during layout animations. Because layout animates using transform: scale(), a resizing parent will stretch its text and images. Fix: add layout="position" to children whose position should move but whose scale should not change [citation:9][citation:14]. This is the single most common layout animation bug.

LayoutGroup — synchronised animations

Layout animations only fire when the element itself re-renders. If two sibling components affect each other's layout but re-render independently, they get out of sync. Wrap them in LayoutGroup and their layout changes animate together [citation:4][citation:14].

layout-group.tsx
import { LayoutGroup, motion } from 'motion/react';

<LayoutGroup>
  <motion.div layout />
  <motion.div layout />   // both animate together
</LayoutGroup>
Quick check · 05
A card expands with layout, and the text inside stretches unnaturally. What's the fix?
layout="position" tells Framer Motion to animate only the element's position, not its size — so text stays at its natural aspect ratio while the container resizes.
07

Scroll effects

whileInView · useScroll · useTransform · useSpring

Two different kinds of scroll animation, two different tools:

What you wantTool
"Animate when this element scrolls into view"whileInView (one line)
"Map scroll position to a value" (parallax, progress bar)useScroll + useTransform

whileInView — the simple case

in-view.tsx
<motion.section
  initial={{ opacity: 0, y: 30 }}
  whileInView={{ opacity: 1, y: 0 }}
  viewport={{ once: true, margin: '-100px' }}
  transition={{ duration: 0.6 }}
/>

once: true means it fires the first time and never again — the right choice for landing page sections [citation:3][citation:13]. margin adjusts the trigger point (negative = trigger earlier).

useScroll + useTransform — scroll-linked values

For parallax, progress bars, or anything that needs to track scroll continuously, you use useScroll (which returns Motion Values) and useTransform (which maps one range to another).

parallax.tsx
import { motion, useScroll, useTransform, useSpring } from 'motion/react';

function ParallaxHero() {
  const { scrollYProgress } = useScroll();

  // smooth out the raw scroll value
  const smooth = useSpring(scrollYProgress);

  // map scroll 0→1 to y 0→-100
  const y = useTransform(smooth, [0, 1], [0, -100]);

  // map scroll 0→0.3 to opacity 1→0
  const opacity = useTransform(smooth, [0, 0.3], [1, 0]);

  return <motion.div style={{ y, opacity }}>Hero</motion.div>;
}
Why Motion Values bypass React

useScroll returns Motion Values, not state. They update on every scroll event without triggering a React re-render. You pass them directly to style, and Framer Motion applies the transform to the DOM node. That's why scroll-linked animations can run at 60–120fps while your component tree stays quiet [citation:12][citation:8].

Quick check · 06
Why does useScroll not cause your component to re-render on every scroll?
Motion Values are a parallel system. They track values and drive animations outside React's render cycle. Passing them to style lets Framer Motion mutate the DOM node directly — high-performance scroll effects without render thrash.

Springs & transitions

physics over duration · stiffness · damping · the feel table

By default, most Framer Motion animations use springs, not durations. Springs are physics-based: they respond to interruption naturally and feel more alive than a fixed-duration tween.

spring-config.tsx
<motion.div
  animate={{ x: 100 }}
  transition={{
    type: 'spring',
    stiffness: 300,   // how hard it pulls toward the target
    damping: 25,     // how much it resists overshooting
  }}
/>
FeelStiffnessDampingUse for
Snappy50030Buttons, toggles, tabs
Smooth30025Cards, panels, modals
Gentle20020Page transitions, hero sections
Bouncy40015Notifications, playful UI
💡
The no-bounce rule. Damping ratio below 1 causes overshoot (bounce). For a spring that settles without bouncing, set damping ≥ 2 × √stiffness. If you want bounce, use it deliberately — not on every element [citation:13].
09

Performance & bundle size

LazyMotion · transform properties · reduced motion

Framer Motion's full bundle is around 34 KB gzipped. That's fine for most apps, but if you only need fades and simple transforms, you can cut it to under 5 KB with LazyMotion.

lazy-motion.tsx
import { LazyMotion, domAnimation, m } from 'motion/react';

function App() {
  return (
    <LazyMotion features={domAnimation}>
      <m.div animate={{ opacity: 1 }} />
    </LazyMotion>
  );
}

m is a lightweight replacement for motion — same API, smaller bundle. domAnimation includes the features most apps need (transforms, gestures, exit animations). Only use the full motion import if you need layout animations or SVG path drawing [citation:3].

Respect reduced motion

reduced-motion.tsx
import { MotionConfig } from 'motion/react';

<MotionConfig reducedMotion="user">
  <App />
</MotionConfig>

This disables motion for users who have "reduce motion" enabled in their OS. Not optional — large parallax and movement can cause nausea for people with vestibular disorders [citation:3][citation:6].

Interview questions

what you'll actually be asked

Q1What is Framer Motion, and what does it give you over CSS?

A React animation library (now called Motion) that turns animation into declarative props. Over CSS it adds: exit animations on unmount (AnimatePresence), layout animations on re-render (layout), gesture states (whileHover, drag), scroll-linked values without re-render (useScroll), and spring physics that respond to interruption. CSS handles simple transitions fine; Framer Motion handles anything that depends on React state or DOM changes.

Q2What is AnimatePresence and why is it needed?

React unmounts components synchronously — the element is gone from the DOM before any exit animation could run. AnimatePresence intercepts removal, keeps the element in the tree until its exit animation finishes, then unmounts it. Without it, exit animations are impossible in React [citation:3][citation:9].

Q3What are the two most common reasons an exit animation doesn't fire?

(1) AnimatePresence is inside the conditional and unmounts along with its children — it must stay mounted. (2) A direct child is missing a unique key — without one, React can't track which element is exiting [citation:3][citation:6].

Q4What's the difference between animate and whileHover?

animate is the target state the component should hold. whileHover is a transient state that applies only while the pointer is over the element, and reverts automatically when it leaves. Same idea for whileTap, whileFocus, whileDrag, whileInView.

Q5What does the layout prop do, and how does it work under the hood?

It animates an element to its new size and position whenever a React re-render changes its layout — without you providing a from-value. Under the hood it uses FLIP: measure First, update state, measure Last, Invert the difference with a transform, then Play the animation back to zero [citation:3][citation:14].

Q6Why does text stretch during a layout animation, and how do you fix it?

layout animates using transform: scale(), which stretches everything inside the element. Adding layout="position" to child elements makes them animate only their position, not their scale — so text stays at its natural aspect ratio [citation:9][citation:14].

Q7What is layoutId used for?

Shared element transitions. Give two elements that are never mounted at the same time the same layoutId, and Framer Motion animates between them as if they're one element. This is how the "card expands into modal" effect works [citation:9][citation:14].

Q8How do scroll-linked animations work in Framer Motion?

useScroll() returns Motion Values (like scrollYProgress) that update without re-rendering React. useTransform(value, inputRange, outputRange) maps one range to another. You pass the transformed value directly to style — e.g. style={{ y }} — and Framer Motion applies it to the DOM node directly [citation:12][citation:8].

Q9Should you animate width/height or scale? Why?

scale (and x/y/rotate). These compile to transform, which the GPU can composite without recalculating layout. Animating width/height/top/left forces the browser to run layout on every frame, which is dramatically slower and causes jank on mobile [citation:10][citation:13].

Q10What's the difference between motion and m?

m is the lightweight version of motion, used with LazyMotion. It has the same API but loads only the animation features you specify (e.g. domAnimation). This cuts the bundle from ~34 KB to under 5 KB. Use it when you don't need layout animations or SVG path drawing [citation:3].

Q11How do you handle reduced motion?

Wrap your app in . This automatically disables motion for users who have "reduce motion" enabled in their OS. It's an accessibility requirement, not a nicety — large movement and parallax can trigger nausea for people with vestibular disorders [citation:3][citation:6].

Q12When would you NOT use Framer Motion?

Simple hover/focus transitions where CSS is enough. List add/remove animations where @formkit/auto-animate is 10× smaller. Long timelines with overlapping keyframes or SVG morphing, where GSAP is stronger. 3D scenes (Three.js / React Three Fiber). Framer Motion is for React-driven UI animation — not for every animation problem.
